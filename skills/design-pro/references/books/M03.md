# M03 — Mobile Card Interfaces

**Source:** UXPin, *Timeless Mobile UI Design Trends: Mobile Card Interfaces*, copyright 2015; Jerry Cao, Carrie Cousins and Ben Gremillion. Original filename: `Mobile Design/Mobile Card Interfaces.pdf`. Locators are PDF pages.

## Principles and applications

- **Group a coherent unit, not every fragment.** A card is a content container representing a thought or primary action (pp. 8–10). The AirDrop accept/decline example contains one decision with two choices, not a literal one-button constraint. Size cards for summary, detail or an overlay according to the information need (pp. 21–22).
- **Choose a container pattern for the task.** The book distinguishes narrative streams, discovery, conversations and workflows (pp. 16–20). These are use cases, not reasons every interface needs bordered rectangles.
- **Use proximity before extra chrome.** In WeChat, avatar and message form a perceptual unit through closeness (p. 19). The screenshot shows sender grouping and differing message alignment, not a separate framed panel around every row. For a chatbot, use coherent sender/message grouping and visible separation between turns; this application is design-pro synthesis.
- **Preserve hierarchy within a container.** Use purposeful spacing, readable text and sufficient contrast over images (pp. 26–28). Consistent depth can explain an overlay; shadows on every side can undermine the depth metaphor (p. 27). Do not add gradients or nested panels solely to signal a card.
- **Adapt the unit across widths.** Cards can restack between columns and a narrow stream (pp. 8–10). Content still needs useful order and readable dimensions. A card does not make arbitrary content responsive automatically; that qualification is synthesis.

## Visual examples

Yahoo Fantasy contrasts compact roster entries with an expanded player-detail overlay (pp. 21–22); their presentation changes with the information needed. Google Maps keeps the map as context while a lower location surface expands (p. 30). This supports preserving context for details rather than navigating away in every case. Spotify's discovery screens (p. 18), Pinterest (p. 23) and Hotel Tonight (p. 24) illustrate different density and image emphasis, not one universal card template.

## Exceptions and source critique

The source describes disguised advertising and difficult-to-activate dismiss links as an integrated experience (pp. 12–13). Do not carry that treatment into design-pro: advertising should be identifiable and a dismissal should be usable. This is a deliberate design-pro rejection of the source's favorable framing, not a technique endorsed by the skill.

Statements that cards are inherently easy, always support thumb interaction, dominate 2015 or are the best method for heavy content (pp. 6–7, 16, 29–33) are promotional/historical generalizations. Dense comparison tables or simple lists may serve a task better; test the actual use case. Some card actions also need discoverable alternatives to gestures; the book's physical-deck metaphor does not establish accessibility.

## Reusable decisions

For the game page, do not wrap every paragraph in a card; use containers only for distinct comparable or independently actionable content. For chat, group a message with its relevant author and state, and keep retry feedback attached to the affected turn. These are design-pro applications of pp. 8, 19 and 27.
