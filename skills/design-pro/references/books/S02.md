# S02 — The Critical Components of Web UI Style Guides

**Source:** UXPin, *The Critical Components of Web UI Style Guides*, copyright 2015. Original filename: `Style Guides/The Critical Components Of Web UI Style Guides.pdf`. Locators are PDF pages.

## Relationship to S01

Pages 6–23 substantially repeat the overview, four guide types and examples in [S01](S01.md). Treat this as overlapping editorial material, not independent validation of the same recommendation. The useful extension is the component-by-component discussion on pp. 24–48.

## Practical guidance

- **Document the decisions people need to reproduce.** Layout guidance includes outer spacing, element gaps, global placement, column behavior and supporting examples (pp. 27–28). Record actual project tokens and responsive behavior rather than copying Drupal's 12-column sample as a rule for all interfaces.
- **Define type by role.** Specify headings, body, captions, bylines and link treatments, with rendered examples and implementation information (pp. 29–30). The Ubuntu type samples show the chosen face and size in context. Values such as 45 px are examples, not universal heading recommendations.
- **Give colors roles as well as values.** Define usage and compatible combinations, not just hue names (pp. 31–32). Include only color representations needed by actual media; a digital-only prototype does not automatically need Pantone or CMYK specifications. The final qualification follows the proportionality principle on pp. 24–25 and 48.
- **Specify media behavior.** Record ratios, cropping/alignment, captions and relevant controls (pp. 32–34). Animation examples need playable behavior, since a screenshot alone cannot communicate motion (p. 34).
- **Show legitimate pattern variants.** Document special modifications and inspect overlap or contradiction (pp. 40–41). Consistency does not mean erasing a deliberate variant used for a different task. Explain unique patterns because a new maintainer cannot infer their rationale.
- **Pair copy with the user's state.** Writing guidance can distinguish voice, grammar, terminology and context. The MailChimp example considers the emotion attached to a pattern (pp. 44–46). For an error, understandable recovery matters more than a promotional tone; that application is design-pro synthesis.
- **Keep implementation next to the pattern.** Reusable examples can accompany components or be organized separately as appropriate (pp. 46–48). Use the project's actual component API; do not prescribe duplicated CSS snippets in a component-based system.

## Coordination and retrieval

Naming and directory conventions help maintain a shared vocabulary (p. 39). Icon catalogs pair visual examples with their coded names and dimensions (pp. 38–39). A lightweight pattern library with rationale, implementation notes and working examples can suffice (p. 41). A searchable guide only succeeds if users can find information without following inconsistent labels across sections (p. 48).

The UX-documents section proposes consolidating personas, research and design artifacts (pp. 42–43). For design-pro, keep reusable sources inside the skill and project briefs/evaluations outside it as the user explicitly requested. A reference can link to project evidence without turning the skill into a store of unrelated project facts.

## Applications and limits

For both demos, define semantic control variants, spacing roles, type roles and recovery copy where needed. A game page can use a distinctive heading style while the chat app uses a quieter reading scale; they do not need an identical visual skin. These are synthesized applications of contextual guidance and pattern variants.

The component list is explicitly a menu of suggestions, not a mandatory checklist (pp. 24–25, 48). Logos, prices, vendor tools and sample style-guide code are historical. Static examples and code snippets do not prove keyboard, assistive-technology or responsive behavior.
