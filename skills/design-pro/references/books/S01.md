## Choose the artifact for the decision

- **Mood board:** explore atmosphere and artistic direction before details are settled (pp. 10–12). Good for discussing a game's mood; insufficient for interaction specifications.
- **Style tile:** test concrete type, colors, controls and visual treatment without fixing screen layout (pp. 12–13). Useful when translating an established brand into a UI or comparing visual directions. A tile does not prove a screen flow works.
- **Brand guide:** record identity, logo usage, colors, typography, imagery and voice where relevant (pp. 14–17). Adapt detail to actual needs; do not assume a long corporate manual is necessary.
- **Front-end guide:** connect visual decisions with reusable code and UI patterns (pp. 18–22). Start with established assets and components; document what developers need to build consistently.

## Context matters as much as appearance

The author explicitly asks a style guide to explain why a tabbed layout may fit customization while a scrolling layout fits storytelling (p. 8). Record when to use a pattern and its exceptions, not just how it looks. This supports design-pro's separation of operational workflows from source-backed reference knowledge.

Treat the guide as a living shared reference rather than a one-time onboarding PDF (pp. 6–9). Shared naming and code examples help designers and engineers identify existing components before introducing new ones (pp. 8–9). For small projects, include only useful guidance (pp. 22–23).

## Applications

For the Web game page, a visual tile can settle the relationship among title type, artwork, primary action and supporting text before implementing responsive sections. For the Mobile chatbot, start from existing platform components and define only necessary role/state variants. These are design-pro applications; the source does not describe those two demo products.

## Limits and cautions

The cited products, websites, tool extensions and sample brand policies are 2015 examples, not current assets or permissions. “You cannot be too meticulous” in the Adobe example (p. 16) must be read with the source's explicit proportionality guidance (pp. 22–23). Do not normalize every legitimate component variant or turn a mood board into a substitute for usability testing. Current platform rules and actual component behavior require independent checks.
