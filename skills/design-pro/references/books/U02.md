# U02 — Color Theory in Web UI Design

**Source:** Jerry Cao, co-written by Kamil Zieba, Krzysztof Stryjewski and Matt Ellis, *Color Theory in Web UI Design: A Practical Approach to the Principles*, UXPin, copyright 2015 (pp. 2–3, 5–7). Original filename: `User Interface/Color Theory in Web UI Design.pdf`. Locators are PDF pages; body folios match. The contents page's early section numbers do not match actual starts; use the PDF locators below. Page 35 is an image-only vendor promotion.

## Color supports a direction, not a guaranteed emotion

The introduction and color catalogue associate warm/cool/neutral colors with energy, calm, trust, luxury, cleanliness and related themes (pp. 6–15). Examples include Fanta, Facebook, Cadbury, Earth Hour and 03 July. Treat these as the author's visual interpretations and historical cultural associations. The guide does not establish a universal physiological effect, emotional response, business benefit or safety property for each hue. A blue background is not evidence of security; red need not make every interface alarming. Content, audience, cultural context, saturation, lightness and neighboring colors all affect interpretation.

03 July changes background treatments alongside different feature messages (pp. 14–15). This can illustrate coordinated visual emphasis and copy, but the source's “perfect” alignment and attribution to designer intent are interpretations, not user findings. No color is best for every project, a limitation the text itself acknowledges (p. 14).

## Distinguish palette relationships from usable contrast

The wheel diagrams describe hue relationships; they do not measure readable text or identifiable controls (pp. 16–19). The source's “roughly three steps away” clash rule is wheel-dependent and is not a reliable accessibility test. Complementary hue pairs can still have inadequate luminance contrast; red/green difference alone can exclude users. Apply [current text/non-text contrast and use-of-color guidance](../current-accessibility.md), rather than inferring compliance from a visually vivid palette.

The prose calls opposite hues complementary, then also calls different shades of the same hue complementary (p. 18). That conflates a technical relationship with the colloquial sense of “go well together.” For a concrete CSS model, [MDN's `hsl()` reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/hsl), checked 2026-10-25, defines an HSL complement by a 180-degree hue change. This is a relationship in that color model, not a perceptual harmony or contrast guarantee. Do not transfer named pairs across unspecified wheels/models.

The p. 18 wheel, its prose examples and the later red/green assertion do not clearly use one consistent set of named opposites. Record explicit values/model for implementation. The TV safety example's red buttons on green show visual emphasis (p. 19), not proof of accessibility or increased clicking.

## Palette structures are options

- **Monochromatic (pp. 20–21):** variations around one dominant hue can create a coherent direction. Check whether actions/states remain distinguishable; it does not automatically make a product elegant, calm or easy.
- **Analogous (pp. 21–23):** neighboring hues can provide related variation. Use clear functional roles and measure actual text/background pairs; orange text on yellow is not readable merely because the author says so.
- **Complementary (pp. 23–24):** opposing hues can distinguish areas or actions. Do not require high saturation or avoid all desaturated colors. The animated Ondo screenshot cannot establish motion behavior or comprehension.
- **Triadic (pp. 25–26):** a three-point wheel relationship offers a palette starting point. It is not inherently the safest, most secure or most broadly liked scheme. The DocReady case supplies no evidence that triadic colors reduce medical-visit anxiety.
- **Split-complementary (pp. 27–28):** the pictured hue relationships do not support the prose's characterization of any black/white palette plus one accent as split-complementary. Do not teach that shortcut. An attractive Shopify report is an example, not a precise demonstrated classification or universal perceptual result.
- **Tetradic (pp. 28–30):** two complementary pairs offer more possible roles and more coordination work. Four main hues do not guarantee stability; Formlets' faces and many colors are not a recipe to copy. Relative area, saturation, contrast and task role matter more than filling every scheme slot.

These structures help generate alternatives. They do not determine a required color count, emotion, brand identity, click rate or error rate. Choose the simplest palette that expresses the product's direction and distinguishes necessary functions, preserving existing semantics where applicable. This selection rule is design-pro synthesis.

## Reproducible roles and verification

The style-guide section recommends explicit values, samples and conditions of use (pp. 31–32). Mozilla illustrates descriptions plus swatches; Lonely Planet groups grays/primary/secondary colors, names values and offers lookup. Reuse that discipline, not the historical palette itself. Record appropriate screen color values and semantic roles; print CMYK/Pantone values are not interchangeable CSS values. Check state combinations as implemented, including focus, disabled, error and selected states where relevant; these checks are design-pro applications.

The tool list and trial terms are historical (pp. 33–35). They are not verified current recommendations, dependencies or a reason to sign up for services. Existing tokens and local color/contrast inspection may be enough for a project.

## Application to both modes

For the game page, select atmosphere and emphasis consistent with the fictional game's identity while ensuring release details/primary action remain readable over actual artwork. For chat, give message roles and statuses recognizable treatments without encoding failure only as red. Maintain a small set of explicit tokens, evaluate actual foreground/background pairs and inspect altered text/contrast settings. A palette classification alone validates none of these behaviors.
