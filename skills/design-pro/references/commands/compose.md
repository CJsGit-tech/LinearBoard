# compose — 建立內容與任務層次

## Responsibility

How should this content be organized so the primary task is clear?

Read the [shared execution contract](../execution.md) and the applicable mode.

## Execute

Identify the main decision/action, supporting information and genuinely secondary content. Map meaningful groups and their relationships before drawing surfaces. Establish reading order, width, whitespace, alignment and type hierarchy from actual content; do not assume a universal scanning pattern. When the arrangement is consequential, compare different grouping/sequence strategies while preserving the same facts and functionality. Implement the chosen composition in scope and check content growth, task access and order.

## Creative application

For a flat or interchangeable composition, use [composition and visual tension](../concepts/creative-design.md#composition-and-visual-tension). Inspect the page as masses, text regions and gaps. Choose a dominant element and supporting relationships from the actual content; explore different spans, scale or density before adding decoration. A grid should help alignment without forcing each item into a visible box. Preserve a deliberate quiet arrangement when the task needs it.

Explain what changes in the composition and why it supports this brief. Do not turn all sections into the same heading/card rhythm or assume a giant title is the answer. Check the meaningful focal relationship after reflow, alongside content order and access to the primary action. In Mobile, a welcome illustration must yield to the composer and repeated conversation when space is constrained.

## Platform focus

- **Web:** consider wide, intermediate and narrow arrangements; retain comparison when records need aligned columns.
- **Mobile:** prioritize the task within available height while keeping secondary actions reachable and drafts intact.

## Deliver and finish

a coherent composition, a brief priority map and rendered evidence.

Completion: the primary task and required information remain reachable in the checked layouts without clipping or misleading reordering. Predicted reading order is a design hypothesis, not eye-tracking research.

## Example

```text
$design-pro compose mobile "Chat welcome screen: two starting points and an always-reachable composer"
```
