# Create a technical baseline

Use `create-technical-baseline <Project>` after the Product Vision and before milestone planning when the stack or shared constraints are known. The baseline is optional and can be added to an existing project later. Its scope spans milestones.

1. Resolve the project and search all pages of its native Project Documents by title and purpose. Read its vision, planning decisions, user-supplied requirements and any existing baseline. Inspect relevant repository configuration when available. If an observed dependency conflicts with a stated requirement, record the discrepancy without changing either choice.
2. Follow the [technical baseline template](../assets/templates/technical-baseline-template.md). Preserve specified versions, mandatory wording and prohibitions. Consolidate duplicate rules. Distinguish confirmed requirements, proposals and observed implementation. Use only areas relevant to the project.
3. For consequential flows, consult official documentation for the relevant version. Briefly record feasibility, limitations, suggestions and built-in features with direct source links. Label each finding documented, tested in this project, or open. Claim a project test only with its evidence. When evidence is missing, identify the smallest useful check and its owning record if known.
4. Create or revise one native Project Document titled `<Project> — Technical Baseline`. Reuse a matching document and preserve its identity, established decisions and unrelated content. If intent or ownership is ambiguous, ask before replacing a decision. Retain open questions without inventing commitments.
5. Read back the project parent, document ID, rendered sections and links. Report the document link and material open decisions. The command writes only the baseline. Milestone scope, PRD acceptance and feature-level implementation stay with their owners. Route proposed changes across records through sync for review and approval.
